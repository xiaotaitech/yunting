## Why

市面上的听书 App（帆书、微信读书听书、喜马拉雅）内容都锁在自家版权库里：想听的书不一定有，已经拥有的有声书资源也放不进去。大量用户其实已经把有声书文件囤在百度网盘里，但网盘客户端只是个文件浏览器——没有书的概念、没有章节续播、没有倍速和定时关闭、锁屏就断、切设备就得从头找。

本变更要做的是一个「以用户自己的百度网盘为唯一数据源」的听书 App：把网盘里的音频文件夹变成书架上的书，补齐帆书级别的听书体验，同时不托管、不转存、不分发任何音频内容——所有音频始终留在用户自己的网盘账号里。

## What Changes

- 新增 Flutter 跨端客户端（Android + iOS），实现完整听书闭环：授权 → 书架 → 章节 → 播放 → 续播。
- 新增百度网盘 OAuth 2.0 授权登录（scope 固定 `basic,netdisk`），支持 token 自动刷新与解除授权。
- 新增一个极小的 serverless OAuth 代理（唯一的服务端组件），只负责 `code → token` 交换和 `refresh_token` 刷新，用于避免 SecretKey 落到客户端。**它不接触、不缓存、不代理任何音频数据。**
- 新增「文件夹即书」的书目识别层：用户把网盘目录「认领」为一本书，App 按自然序解析章节、读取 ID3/文件名元数据、识别同目录封面图。
- 新增听书播放器：流式播放网盘 dlink、倍速（0.5x–3.0x）、睡眠定时器、快进/快退 15s、后台播放与锁屏/通知栏控制、耳机线控。
- 新增播放进度记忆与跨设备同步：进度、书架、收藏以 JSON 形式写回用户网盘的 `/apps/<应用名>/` 目录，零服务端数据库。
- 新增离线下载缓存：按章节下载到本地、缓存配额管理、无网时自动走本地文件。
- 明确不做（本次范围外）：内容分享、他人网盘/分享链接抓取、听书稿/AI 摘要、社区与评论、付费内容。

## Capabilities

### New Capabilities
- `netdisk-auth`: 百度网盘 OAuth 授权、access/refresh token 生命周期管理、授权失效与解除授权处理。
- `library-catalog`: 把网盘目录识别并「认领」为书，章节自然序解析、元数据与封面提取、书架的增删与排序。
- `audio-playback`: 听书播放器核心——dlink 获取与过期续播、流式播放与缓冲、倍速、睡眠定时器、后台播放与系统媒体控制。
- `listening-progress`: 每本书的播放进度记录、断点续播、以及经由用户网盘 `/apps/` 目录实现的跨设备同步与冲突解决。
- `offline-cache`: 章节离线下载、下载队列与断点续传、本地缓存配额与清理、离线优先播放。

### Modified Capabilities
（无——这是项目的第一个变更，`openspec/specs/` 目前为空。）

## Impact

**新建代码**
- Flutter 客户端（Android + iOS）：`just_audio` + `audio_service`（后台播放与媒体通知）、`just_audio` 的 `userAgent` 参数用于满足百度 dlink 对 `User-Agent: pan.baidu.com` 的强制要求。
- 一个 serverless 函数（约 100 行）承担 OAuth token 交换/刷新。
- 本地持久化：SQLite/Isar 存书架与进度缓存，文件系统存离线音频。

**外部依赖与前置条件**
- 百度网盘开放平台：需注册开发者、实名认证、创建应用，拿到 AppKey / SecretKey / SignKey，并在控制台配置 OAuth 回调地址。
- 百度侧已知约束（会直接影响设计，详见 design.md）：dlink 请求必须带 `User-Agent: pan.baidu.com`，dlink 有时效性且会 302 跳转；分享类接口不对个人开发者开放；非会员账号下载带宽受限；scope 传错会返回 `errno=-6`。

**风险面**
- 网盘限速可能使高码率音频无法流畅流式播放 → 需要缓冲策略与「先下载后听」兜底。
- dlink 过期导致播放中断 → 播放层必须能无感重取链接并从当前位置续播。
- 平台合规：App 仅访问用户自己的网盘数据，不做内容分发，须在设计与文案上明确这一点。
