# 任务清单

## 1. 数据来源

- [x] 1.1 定义续听入口的视图模型（书 + 当前章节 + 断点位置 + 是否就绪），放在 `app/services.dart` 附近，供书架页消费
- [x] 1.2 新增 `continueListeningProvider`：依赖 `shelfProvider`，筛出 `lastPlayedAt != null` 的书并取最新一本；全都没播过时返回 `null`
- [x] 1.3 取该书章节并按 `currentChapterIndex` 定位章节名；章节为空或序号越界时标记为「未就绪」而不是抛错
- [x] 1.4 确认 provider 不触发任何网络调用（只经 `library.shelf()` / `library.chapters()` 的本地路径）

## 2. 续播入口收敛

- [x] 2.1 把 `shelf_screen.dart` 里 `_BookTile._continueListening` 抽成文件级的续播函数，参数为书与上下文
- [x] 2.2 在该函数里加入「播放器已装载同一本书」的短路：比对 `handler.mediaItem` 的 `extras['bookId']`，相同则只 push 播放页，不调 `openBook`
- [x] 2.3 章节为空、序号越界、源文件不可用三种情况给出明确提示（复用历史页 `_resume` 的口径），不静默返回
- [x] 2.4 从播放页退回时 `invalidate(shelfProvider)`，让卡片跟着最新的 `last_played_at` 刷新（不能在 `play()` 之后立刻刷：那时 5 秒一次的进度上报还没写库）；切回书架标签页时同样重取，覆盖从迷你播放条与历史页开始听的路径
- [x] 2.5 列表卡片上的「继续收听」按钮改为调用同一函数

## 3. 首页卡片

- [x] 3.1 在书架列表下方渲染续听卡片：封面 + 书名 + 章节名 + 断点位置 + 该章进度条
- [x] 3.2 `continueListeningProvider` 为 `null` 时整块不渲染（含书架为空的情况）
- [x] 3.3 源文件不可用 / 章节未就绪时卡片可见但播放禁用，并显示原因
- [x] 3.4 书已标记「已听完」时，卡片文案说明点击将从第一章开始
- [x] 3.5 卡片与列表之间留白区隔（原计划的「书架」小标题在卡片移到列表下方后不再需要，AppBar 标题已说明这是书架）
- [x] 3.6 加载与错误态：不因续听卡片的异步失败而挡住整个书架列表
- [x] 3.7 有播放会话时卡片让位给迷你播放条（`nowPlayingProvider`，与播放条同一数据源），避免同一本书在一屏上出现两次且两个进度对不上

## 4. 冷启动行为

- [x] 4.1 核对启动路径（`main.dart` / `RootScreen` / `AudiobookHandler` 初始化）没有任何自动 `play()` 或预加载音源的调用
- [x] 4.2 若存在预热逻辑，确保它 MUST NOT 请求音频焦点或产生声音
